# MiniOB 教学指南 - 写作规范

## 目标读者

本项目教学对象为**大二学生**，具备以下基础：
- 数据结构与算法基础
- C++ 编程能力
- 操作系统基础知识

教学文档编写需考虑学生知识水平，避免过于深奥或跳跃式讲解。本项目基于 MiniOB 开源数据库系统。

### PPT 图片生成任务

**当前阶段**：Day1 PPT 图片提示词优化完成

**任务要求**：所有 PPT 图片统一使用 **nanobanana pro** 生成，风格必须一致。

**风格规范**：
- 整体采用**学术论文插图风格**，克制、清晰、不过度设计
- 以**低饱和度配色**为主，允许少量 `light blue` / 浅灰蓝作为辅助强调色
- 主色建议：白底、深灰线条、浅灰填充，强调区域可用淡蓝色块
- 线条保持细且稳定（约 1-2px），避免夸张描边
- 图形以几何图形为主，可少量圆角，但整体仍需简洁理性
- 无阴影、无发光、无纹理、无强装饰，避免海报化和营销感
- 版式留白充足，层级通过对齐、间距和明度变化体现
- 中文字体以宋体/黑体等稳重风格为主，避免花哨字体

**配色建议**：
- 基础背景：纯白或接近白色
- 主线条：深灰、炭黑，而非纯黑压满全页
- 次级填充：浅灰、冷灰
- 强调色：低饱和浅蓝、灰蓝，例如 `#DCEAF4`、`#C9DCEB` 这一类气质
- 强调色只用于关键模块、高亮路径、重点标注，不要大面积铺色

**提示词格式**：
- 主体描述使用英文，保证模型对构图和风格的理解稳定
- 中文标注单独列出，避免把正文说明和图中文字混在一起
- 明确拆分为：`Task`、`Layout`、`Elements`、`Text Labels`、`Style Constraints`、`Negative Constraints`
- 每条提示词先写图像目标，再写布局，再写元素细节，最后补风格约束与禁止项
- 风格描述不要只写“academic style”，要把颜色、线条、留白、装饰限制写具体

**推荐提示词模板**：

```text
Task:
Create an academic-style presentation diagram for [topic].

Layout:
[Describe the overall composition, reading order, and spatial arrangement.]

Elements:
[List the key objects, arrows, boxes, layers, labels, or relationships that must appear.]

Text Labels:
- 中文1：...
- 中文2：...
- 中文3：...

Style Constraints:
- clean academic paper illustration
- white background
- thin dark gray lines
- light gray and low-saturation light blue fills
- minimal decoration
- balanced whitespace
- clear hierarchy
- professional, calm, understated

Negative Constraints:
- no glossy effect
- no 3D rendering
- no dramatic lighting
- no saturated colors
- no heavy shadows
- no cartoon style
- no marketing poster style
```

**提示词写法建议**：
- 先说清楚这张图是“流程图 / 结构图 / 对比图 / 分层示意图”中的哪一种
- 箭头方向、模块相对位置、层级关系要写死，减少模型自由发挥
- 如果要强调重点，明确说明“only use light blue for key path / key module highlights”
- 图中文字不宜过多，优先保留核心术语，避免整句堆进图片
- 每次生成后从“统一性、可读性、颜色克制程度”三个维度复核

## 核心教学理念

### 循序渐进

教学内容组织遵循"由浅入深"原则：

- **从简单入手**：先介绍最简单、最直观的概念或实现，再逐步扩展到复杂场景
- **逐步迭代**：展示系统如何从最简版本一步步演进为完整版本
- **示例驱动**：用具体、可运行的代码示例讲解抽象概念

**示例**：讲解存储结构时，不要直接跳到复杂的 B+ 树，而是从最简单的 `map<string, string>` 开始，逐步引入持久化、索引等概念。

### 穿插操作系统知识

数据库内核与操作系统紧密相关，适时穿插操作系统概念：

- **存储层次结构**：CPU 缓存 → 内存 → 磁盘的速度与容量差异
- **缓冲区机制**：为什么需要缓冲区、缓冲区如何提升性能
- **I/O 模型**：顺序读写 vs 随机读写、阻塞 I/O vs 非阻塞 I/O
- **进程与线程**：线程池、并发控制、资源复用

### Trade-off 思维

引导学生思考系统设计权衡：

- **空间换时间**：索引占用额外空间，但加速查询
- **时间换空间**：压缩存储节省空间，但解压消耗时间
- **一致性 vs 性能**：严格一致性保证可能牺牲性能
- **复杂度 vs 可维护性**：过度优化增加代码复杂度

鼓励思考："为什么这样不行？基于什么考虑选择了这个方案？放弃了什么？"

### 问题导向学习

采用"带着问题学习"方式：

1. 先让学生思考某需求如何实现
2. 再展示参考实现
3. 对比差异，分析原因
4. 总结设计决策背后的考量

## 文档结构建议

### 标准章节结构

```
1. 引言 / 背景
   - 这个模块/功能是什么？为什么需要它？学习目标
2. 基础知识
   - 相关核心概念、与操作系统/数据结构的关联
3. 从简单到复杂
   - 最简版本实现 → 遇到的问题 → 逐步改进
4. MiniOB 中的实现
   - 代码结构、关键类/函数、流程图
5. 实践任务
   - 具体赛题要求、实现步骤、调试建议
6. 总结与思考
   - 核心要点回顾、延伸思考题
```

### 内容比例建议

| 内容类型 | 比例 | 说明 |
|----------|------|------|
| 概念讲解 | 30% | 核心概念、原理、类比 |
| 流程/结构图 | 20% | 可视化帮助理解 |
| 代码示例 | 25% | 具体实现参考 |
| 操作系统关联 | 15% | 穿插底层知识 |
| 思考/问题 | 10% | 引导学生自主思考 |

## 写作风格

### 语言风格

- **通俗易懂**：避免过多术语堆砌，新术语需解释
- **类比说明**：用学生熟悉的事物类比抽象概念
- **问答式表达**：适当使用"为什么？""怎么办？"引发思考

### 避免

- ❌ 直接给出复杂实现，不做铺垫
- ❌ 假设学生已掌握高级知识
- ❌ 只讲"怎么做"，不讲"为什么"
- ❌ 缺少可视化（流程图、结构图）
- ❌ 忽略设计中的权衡取舍

### 推荐

- ✅ 从学生已知的知识出发
- ✅ 用生活化的类比解释抽象概念
- ✅ 明确指出每个设计决策的原因
- ✅ 配合流程图、架构图辅助理解
- ✅ 强调理论与实践的结合
